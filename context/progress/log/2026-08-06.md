## 런타임 구현 구조 결정 (Codex, Ubuntu)

- Jetson·로봇 전에 B·C·D와 전체 사용자 흐름을 최대한 개발하기로 함.
- 기존 GaP 2Hz 판단 루프를 세션 전체를 관리하는 이벤트 기반 상태 머신으로 확장. UI·Pose·로봇·촬영
  결과는 단일 `asyncio.Queue`로 전달하고 `Coordinator`만 상태를 변경.
- 기본 배포는 Python 프로세스 하나로 유지하고, ROS 2는 phorce 모션/피드백 경계에서만 사용.
- 기능을 줄이지 않되 과설계를 피하기 위해 초기 코드는 8개 내외의 책임별 모듈로 시작. Robot·Capture·
  Camera/Pose처럼 실제 교체가 필요한 경계만 작은 인터페이스로 격리.
- `dev` 설정에서는 `FakeRobot`, `FakeCapture`, 노트북 카메라/녹화 영상으로 구도 선택→가이드→정렬→
  촬영→리뷰→재촬영/확정 전체 흐름을 검증하고, `jetson` 설정에서 실제 구현체로 교체.
